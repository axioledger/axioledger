  1. Overview

The Swift SDK Code Generator enables you to generate your own SDK. Both the Java API Client libraries, including source and examples, will be automatically created for you. This will enable you to make an HTTP call without the need to code additional classes.

In addition to providing the same functionality as swagger-codegen/openapi-codegen, the swift-sdk code generator gives you the security footprint encapsulation required to make a secure HTTP request to Swift Endpoint, including the integration on top of Swift Microgateway. It automatically generates and orchestrates the security models for APIs exposed over MV-SIPN and internet channels. It also generates API samples based on APIs extracted from OAS contracts. RFC 7523 and 7515 will also be automatically implemented for you.

  1. Generate Code in Five Steps

Step 1: Download package 

 Open your Swift-sdk-code-generator package. Here I am opening “swift-sdk-code-generator-1.17.0-SNAPSHOT.zip”.

Quick description of the folder’s structure

  • apidocs: contains general documents about the swift-sdk-code-generator
  • lib: contains mandatory libraries for the code-generator to run
  • src: contains source code of dependent module required for quick start

  • swift-sdk-code-generator-openapi: This is a mandatory module if you are building on OpenAPI-based code. It comes with a default set-up that is ready to run. Note that the pom file comes with a long list of OpenAPI specs that users can modify (depending on the API they are interested in). We will cover more about this further down in the document.
  • swift-sdk-code-generator-swagger: This is a mandatory module if you are building on Swagger-based code. It comes with a default set-up that is ready to run. As a guidance, the pom file comes with a long list of OpenAPI specs that users can modify (depending on the API they are interested in). We will cover more about this further down in the document.
  • swift-sdk-codegen-lib: This module provides the minimum libraries for a quick start of the code generator. It essentially gives the user default implementation of the SDK common interface, including security-sdk. It is mandatory for a quick start, as the user would not have a default implementation of the SDK common interface (look at the Security SDK interface folder).
  • Swift-sdk-config-manager: This module enables the user to process an SDK-encrypted file and fetch the global config set in config-swift-connect.yaml. For further details, please refer to SDK documentation “SWIFT SDK for Java Version 1.1.1 Configuration Management Guide” under section “Configuration File Encryption (YAML file).”  Although this module is production-ready, it is only mandatory for test purposes. User has the option to code or use their own interface for configuration management.
  • swift-sdk-openapi: For OpenAPI-based code. It is a skeleton for the code-generator to generate a clean set-up. It stores the .openapi-generator-ignore that prevents the code-generator from creating redundant files.
  • swift-sdk-swagger: For Swagger-based code. This module is optional. It is a skeleton for the code-generator to generate a clean set-up. It stores the .openapi-generator-ignore that prevents the code-generator from creating redundant files.

  • test-data: It provides users with a large selection of RequestBody in YAML format. This is useful for tests, as the user can use YAML serialisation or deserialisation to quickly make a Java object out of it. This folder is optional, as it is automatically regenerated each time you run the code-generator. Its output path could be set under src/main/resources/generator.properties through parameter outPutExamplesFilepath

Step 5: Configure SDK

Set the SDK config file config-swift-connect.yaml and encrypt it with file-encryptor-decryptor-2.17.0.jar. Please read config_encrypt_instructions.txt for further details. Also, refer to SDK documentation “SWIFT SDK for Java Version 1.1.1 Configuration Management Guide” under section “Configuration File Encryption (YAML file)”.

Once done, please copy the following resource into C://SWIFT/ (Windows) or /opt/SWIFT/ (Linux):

  • from your encryption, file: config-swift-connect-yaml.enc
  • from your encryption, file: util4config
  • from package, file: config-swift-sdk-properties.yaml
  • from generator path (check src/main/resources/generator.properties), folder: test-data

Also, create an SDK keystore (storing HTTP Server certificate and Alliance Gateway server if used) and copy it to the same location.

  1. OpenAPI Spec Pre-processing Validation

It is common to face issues during code generation when the OpenAPI spec is not set properly or has some complex or conflicting data structure set-up with polymorphism (for example, oneOf, anyOf, or manyOf). As such, we have integrated into this code-generator release a Java module called swift-sdk-oas-remediator that you can find under the lib folder of the zip package as swift-sdk-oas-remediator-x.x.x.jar.

The swift-sdk-oas-remediator will run as a Maven plug-in under code-generator pom.xml.

It comes with property file remediator.properties, where you have to set two main entries:

  • openApiSpecPath = directory tree of your oas files
  • app.running.mode = app-running mode where:
  • default: swift-sdk-oas-remediator is disabled
  • fix: find all potential issues with oas file reported them in the logs and attempt to correct them
  • trace: find all potential issues with oas file reported in the logs

This module will run as part of the maven clean command. It supports both YAML and JSON files. Please note that JSON files will automatically be converted into YAML. Your Pom.xml must be set with a ‘.yaml’ file, but your directory will be loaded with a ‘.json’ file.

  1. GENERAL TROUBLESHOOTING AND NOTES

Case 1: Unable to find enum value '002' for enum class

Java does not support numbers as an enumeration. If you see an error like that, then it means your model file is using a number as an enumeration. To work around that, the code generator uses an underscore “_” prefix. As such, you must edit the corresponding file and update the number with a “_” prefix.

Case 2: OneOf, AllOf or AnyOf construction

Code generators are very sensitive with concepts like OneOf, AllOf and AnyOf. If you are having problems with this set-up, then please consider the following:

  • Fall back to String
  • Comment the OneOf, AllOf or AnyOf

By default, both swagger-codeGen and open-api-codeGen use maps to resolve complex inheritance and composition definitions for expressions like OneOf, AllOf and AnyOf.

Case 3: Pom.xml is set with “.json” file and app.running.mode is set to FIX. However, there are error messages about a missing JSON file.

The OneOf remediator works by default with a YAML file. The JSON file will be automatically converted into YAML. As such, if you want OneOf to be remediated on the JSON file, please make sure you follow the steps below:

1) Put your JSON file into CodeGen OpenAPI Spec folder

2) Set your pom.xml with .yaml rather than .json

3) Run the CodeGen
